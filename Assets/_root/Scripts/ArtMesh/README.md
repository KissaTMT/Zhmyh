# ArtMesh

Деформируемые плоские детали (арт-меши) для 3D-сцены в духе Live2D. Деталь — это один радиальный меш,
построенный по спрайту и залитый цветом (с обводкой). Форма в разных ракурсах задаётся **видами**:
каждый вид хранит направление камеры (yaw 0…360, pitch), трансформ (scale, offset с глубиной по Z), смещения
сетки деформации и правки отдельных вершин. В рантайме виды смешиваются по направлению камеры.

- **Рантайм и редактор полностью разделены.** Рантайм-сборка не содержит ни одной функции редактора и не знает про зеркало.
- Спрайты нужны только в редакторе: по одному строится меш, другим можно воспользоваться как образцом контура.
  В билд спрайты и текстуры не попадают.
- Билбординга нет: деталь ориентируется как обычный объект сцены.
- Деформация считается на GPU (вершинный шейдер). Меш статичен и общий для всех экземпляров.
- Данные видов лежат в ScriptableObject `ArtMeshAsset`, данные авторинга (спрайты, параметры построения) в отдельном
  редакторском файле рядом с ним.
- Вся работа в редакторе идёт через окно **Tools → ArtMesh → Editor**.

---

## Требования

- Unity 2020.2 или новее (`Handles.FreeMoveHandle` новой сигнатуры, `Mesh.SetUVs` с `Vector2[]`).
- Шейдер `ArtMesh/FlatDeform` написан на CG с `#pragma target 3.5` (нужен `SV_VertexID` и чтение текстуры в вершинном шейдере).
  Работает в Built-in. В URP/HDRP проверь на своём проекте.
- У спрайта, по которому строится меш (и у спрайта-образца контура): Read/Write включён, Mesh Type = Full Rect,
  без упаковки в SpriteAtlas.

## Установка

Скопируй папку `ArtMesh` в `Assets/`. Внутри две сборки:

| Сборка | Папка | Содержит |
|---|---|---|
| `ArtMesh.Runtime` | `Runtime/` | компонент, данные, математика, источники вида, шейдер |
| `ArtMesh.Editor` (только Editor) | `Editor/` | окно, вкладки, инструменты, данные авторинга |

Пространства имён: `ArtMesh` (рантайм) и `ArtMesh.Editor` (редактор). Рантайм не ссылается на редактор.

---

## Быстрый старт

1. **GameObject → ArtMesh → Art Mesh Part.** Создаётся объект с `ArtMeshRenderer`, материалом по умолчанию
   (`Assets/ArtMesh/ArtMeshDefault.mat`) и открывается окно ArtMesh Editor.
2. Вкладка **Mesh**: «Создать ArtMeshAsset…» и сохрани ассет. В нём сразу есть вид **Base**.
3. Задай **Source Sprite** и нажми **Bake mesh**. Меш сохранится как под-ассет файла `ArtMeshAsset`.
4. Задай цвет заливки и обводки в блоке «Appearance».
5. Вкладка **Views**: добавь виды, выбери нужный и нажми **Редактировать**.
6. Вкладка **Proxies**: «Прокси сетки» (грубая форма) или «Прокси вершин» (точная подгонка).
   Двигай точки стандартными инструментами Unity (W/E/R).
7. Закончив, нажми «Стоп» на виде и «Удалить прокси». Данные остаются в ассете.

Чтобы посмотреть виды без камеры, на вкладке **Views** включи «Предпросмотр направления без камеры».

## Основные понятия

**Базовый меш.** Радиальная сетка: центральная вершина (якорь) и `rings` колец по `rays` вершин. Раскладка хранится в
`ArtMeshAsset.topology` и общая для всех видов.

**Вид (`ArtMeshView`).** Данные одного ракурса:

| Поле | Смысл |
|---|---|
| `yaw` | 0…360: 0 = камера на +Z детали, 90 = на +X, 180 = сзади, 270 = на −X |
| `pitch` | −90…90, > 0 = камера выше |
| `scale` | масштаб, как Scale в GameObject |
| `offset` | позиция, как Position. **`offset.z` = глубина вида** |
| сетка (`latticeDelta`) | 3D-смещения узлов сетки деформации |
| правки вершин (`vertexDelta`) | финальные 3D-смещения отдельных вершин поверх сетки |

**Полный круг без отражения.** Направление — вся сфера. Левой и правой сторон как отдельных понятий нет: каждый вид
настраивается вручную и смешивается по своему направлению. Если на какой-то стороне видов нет, смешивание берёт ближайшие.

**Сетка деформации.** Регулярная решётка 2×2 … 8×8 узлов над формой, сглаживание Catmull-Rom.

**Правки вершин.** Мелкие финальные корректировки после сетки.

**Смешивание видов.** Вес вида = 1 / (угол до направления камеры)^`weightPower` (Shepard), веса нормируются.
Нужен вид Base с yaw 0 и без смещений, иначе единственный вид будет применяться ко всем углам.

**Зеркало — только функция редактора.** В рантайме понятия зеркала нет. Для ускорения работы есть кнопка **«Зеркало»**
у каждого вида (и «+ Зеркало выбранного» в строке создания видов). Она создаёт обычный новый вид:

- `yaw' = 360 − yaw`, тот же `pitch`, `offset.x' = −offset.x`, сетка отражена, а правки вершин подобраны так, чтобы
  форма была точным зеркальным образом исходной;
- вершины переставляются на ближайшие зеркальные (перестановка по кольцам и лучам, подбираемая автоматически),
  поэтому меш не выворачивается и обход треугольников сохраняется;
- результат — независимый вид, который можно править вручную как любой другой.

## Системы координат

- Деталь лежит в плоскости **XY** своего Transform; «перед» детали — ось **+Z**.
- **Глубина:** +Z = ближе к камере на yaw 0. Глубина вида хранится в `offset.z`, глубина отдельных точек — в Z их смещений.
- Направление считается от детали к камере (`viewCamera` или `Camera.main`) в осях `viewSpace` (по умолчанию сама деталь).
  Можно указать кость (например голову), и тогда виды будут зависеть от её поворота.

## Окно ArtMesh Editor

Открывается через **Tools → ArtMesh → Editor** или кнопкой в инспекторе `ArtMeshRenderer`. Следует за выбором объекта;
кнопка **Lock** фиксирует цель.

### Вкладка Mesh
- Ассет, материал, внешний вид (цвет заливки, обводка).
- Данные авторинга: Source Sprite, якорь (авто или вручную хэндлом в Scene View), параметры построения
  (`rays`, `rings`, `ringBias`, `rimSmooth`, `alphaThreshold`).
- Разрешение сетки и `weightPower`.
- **Bake mesh** — построить меш по Source Sprite.

### Вкладка Views
Предпросмотр направления без камеры (yaw 0–360, pitch). Список видов с параметрами и кнопками «Редактировать»,
«Взять направление», «Зеркало», «Сброс», «X». Внизу: «+ Base», «+ Вид из текущего» (копия текущего состояния в текущем
направлении), «+ Зеркало выбранного».

### Вкладка Proxies
Создаёт GameObject-прокси для редактируемого вида: «Прокси сетки» (по объекту на узел) и «Прокси вершин» (по объекту на вершину).

- Двигай, вращай, масштабируй выбранные точки обычными инструментами Unity (W/E/R, snapping, Undo). Z точки = её глубина.
- **Корень прокси = трансформ вида:** Position → `offset` (включая Z), Scale → `scale`. Поворот не поддерживается.
- «Мягкое влияние» (по умолчанию выключено, 0) подтягивает соседние точки с затуханием. Радиус задаётся в **шагах топологии**
  (ячейки сетки или шаги по кольцам и лучам), а не в мировых единицах.
- Помощники выбора: все, инверсия, строка/столбец/контур сетки; центр, кольцо, луч, внешнее кольцо.
- «Проверить совпадающие точки» выделяет прокси, стоящие в одной позиции.

Прокси — обычные объекты без компонентов с флагами `DontSaveInEditor | DontSaveInBuild`. После Undo/Redo они
расставляются заново по данным ассета.

### Вкладка Contour
Подгонка вершин по контуру вспомогательного спрайта (Contour Sprite в данных авторинга).

- **Подогнать внешнее кольцо по контуру:** выбранные вершины кольца притягиваются к ближайшей точке контура,
  остальные расставляются равномерно по свободному участку. Внутренние кольца идут следом.
- **Привязать выбранные к контуру** и **Выбрать вершины кольца вне контура**.
- Контур можно отразить по X. Он виден голубой линией при редактировании вида в любом режиме.

**Блокировка участка кольца.** Заблокированные вершины (красные) не двигаются при прокрутке; «Выбрать дугу» берёт участок
от луча до луча.

**Прокрутка вершин по контуру.** «Начать прокрутку» запускает сессию с ползунком «Сдвиг (слоты)»:

- без блокировок кольцо целиком сдвигается вдоль контура, сохраняя текущее распределение;
- с блокировками заблокированные стоят, а свободные вершины равномерно распределяются по свободному куску контура и
  сдвигаются по нему, плавно прижимаясь к заблокированным соседям и не проходя сквозь них;
- ползунок считается от снимка, его можно крутить туда-обратно; «Применить» фиксирует, «Отмена» возвращает исходное.

Контур — граница самой большой связной области альфа-маски спрайта (Moore-трассировка, 512 точек). Сравнение идёт с формой
**после** трансформа вида; глубина Z вершин не меняется. Пивот спрайта-образца должен совпадать с пивотом Source Sprite.

## Типичные сценарии

### Полный оборот головы
1. Base (yaw 0), без смещений.
2. Вид на yaw 90: «+ Вид из текущего» при предпросмотре yaw 90, подгони сеткой и контуром бокового спрайта.
3. Вид на yaw 270: кнопка «Зеркало» на виде 90 даёт заготовку, при необходимости поправь вручную.
4. Вид на yaw 180 (сзади): отдельный вид; чтобы голова «исчезала» сзади (её закрывают волосы), выбери корень прокси и
   уменьши Scale по X почти до нуля.
5. Промежуточные углы (45°, 135°, 225°, 315°) добавляй отдельными видами.

### Слои и глубина
Задавай `offset.z` вида или Z отдельных точек, чтобы детали не перекрывались неправильно. Обводка отодвигается от камеры
вдоль Z детали автоматически.

## Использование в рантайме

Компонент `ArtMeshRenderer` читает `ArtMeshAsset` и обновляется в `LateUpdate`.

```csharp
var part = GetComponent<ArtMesh.ArtMeshRenderer>();
part.Asset = myAsset;                          // сменить ассет
part.Appearance.fillColor = Color.red;
float yaw = part.Yaw, pitch = part.Pitch;      // текущее направление: yaw 0…360
```

### Источники вида (отдельный слой)

Откуда компонент берёт форму, определяет `IArtMeshViewSource`. Через него редактор, тесты и кат-сцены управляют
компонентом, не требуя от него специальных режимов:

| Источник | Поведение |
|---|---|
| `CameraViewSource` (по умолчанию) | направление от камеры, виды смешиваются |
| `ManualViewSource(yaw, pitch)` | направление задано углами, виды смешиваются |
| `FixedViewSource(view)` | ровно один вид без смешивания |

```csharp
part.ViewSource = new ArtMesh.ManualViewSource(90f, 0f);   // тест: смотреть сбоку
part.ViewSource = null;                                    // вернуть камеру
```

Свой источник — реализуй интерфейс и назначь в `ViewSource`.

## Данные

- `ArtMeshAsset` (ScriptableObject): меш (под-ассет), раскладка вершин (`topology`), конфиг сетки, область сетки, виды.
- `ArtMeshAuthoring` (только Editor): Source Sprite, Contour Sprite, якорь и параметры построения. Лежит рядом с ассетом
  файлом «Имя.authoring.asset», создаётся автоматически и в билд не попадает. Не переименовывай ассет без этого файла.
- Каналы меша: UV0 = внешняя нормаль вершины (для обводки), остальные UV свободны.
- При смене разрешения сетки смещения видов передискретизируются. При смене топологии меша (rays/rings) правки вершин
  видов сбрасываются с предупреждением в консоль.

## Архитектура

### Runtime (`ArtMesh`)

| Класс | Ответственность |
|---|---|
| `ArtMeshAsset`, `ArtMeshView`, `ArtMeshTopology`, `ArtMeshAppearance` | данные |
| `ArtMeshState` | вычисленное состояние формы |
| `ArtMeshViewDirection` | направление «деталь → камера», углы |
| `ArtMeshViewBlender` | смешивание видов |
| `IArtMeshViewSource`, `CameraViewSource`, `ManualViewSource`, `FixedViewSource` | откуда берётся форма |
| `ArtMeshEvaluator`, `ArtMeshGeometry`, `LatticeMath` | CPU-вычисление формы (то же, что шейдер) |
| `ArtMeshRenderBinder` | передача состояния в материал |
| `ArtMeshRenderer` | тонкий компонент; внутренние объекты создаются лениво (`EnsureInitialized`) |
| `ArtMeshFlat.shader` | деформация на GPU |

### Editor (`ArtMesh.Editor`)

| Группа | Классы |
|---|---|
| Данные авторинга | `ArtMeshAuthoring`, `ArtMeshAuthoringRepository`, `ArtMeshBuildSettings` |
| Построение | `RadialMeshBuilder` (спрайт → данные), `ArtMeshBaker` (данные → под-ассет) |
| Виды | `ViewOperations`, `ViewMirrorService`, `MirrorPermutation` |
| Контур | `Contour`, `ContourExtractor`, `ContourArcs`, `RimFitter`, `RimSpinner`, `RimSpinSession`, `ContourProvider`, `ContourFitService`, `ContourFitOptions`, `ViewTransform` |
| Прокси | `ProxySession`, `ProxyFactory`, `ProxyGeometry`, `ProxySynchronizer`, `SoftFalloff`, `ProxySelectionTools`, `ProxyDiagnostics`, `ProxyRegistry`, `ProxyGizmos`, `ProxyOverlay`, `ProxyOptions` |
| Сцена | `SceneViewAligner`, `AnchorHandleTool`, `WireframeGizmo` |
| Окно | `ArtMeshEditorWindow` (хост), `ArtMeshEditorContext` (состояние), вкладки `MeshTab` / `ViewsTab` / `ProxiesTab` / `ContourTab`, `ArtMeshAssetCreator`, `ArtMeshRendererInspector` |

Редактор управляет компонентом только через публичный слой `ViewSource`; в редакторе нет MonoBehaviour.

## Шейдер: зачем он нужен

Вся деформация (сетка, правки вершин, scale/offset, обводка) считается в вершинном шейдере. Плюсы: меш статичен и общий для
всех экземпляров, на CPU уходит только небольшой массив сетки и буфер правок вершин. Минусы: шейдер привязан к пайплайну и не
умеет стандартное освещение. Если понадобится стандартный материал, можно добавить режим деформации на CPU: математика уже есть в
`ArtMeshEvaluator`. Правки вершин передаются в шейдер 1D-буфером `RGBAFloat` на экземпляр (индекс = `SV_VertexID`).

## Ограничения и частые проблемы

- **Обновление со старой версии.** Формат меша и данных видов изменился (убраны зеркало и стороны, yaw теперь 0…360):
  пересоздай ассеты и запеки меш заново (Bake). Старые виды с yaw в −180…180 нужно перенести вручную.
- **Меш розовый или не виден.** Проверь шейдер (`ArtMesh/FlatDeform`) и что меш запечён.
- **«Текстура … не читаема».** Включи Read/Write у текстуры спрайта (Source Sprite и Contour Sprite).
- **Нет обводки.** У меша должно быть два сабмеша (делает Bake).
- **«Зеркало» не работает.** Меш должен быть радиальным и запечённым этой версией (проверь, что `topology` заполнена).
- **Предупреждение «правки вершин сброшены».** Изменилась топология меша (rays/rings). Правки вершин привязаны к индексам.
- **Контур не находится.** Спрайт-образец пустой по альфе или `alphaThreshold` слишком велик.
- **Форма не радиальная** (длинные прядки, отдельные части): радиальный меш предполагает звёздчатость относительно якоря.
  Несколько мелких деталей лучше делать отдельными ArtMesh.
- **NullReferenceException в `ArtMeshRenderer`.** Внутренние объекты создаются лениво в `EnsureInitialized()`; если добавляешь
  публичный метод, вызови его первым.
- **Две прокси стоят в одном месте.** «Проверить совпадающие точки»; при включённом мягком влиянии радиус больше 0 двигает и соседей.
- Максимальное разрешение сетки 8×8 (размер массива в шейдере). Максимум вершин: 128 лучей × 24 кольца + 1 = 3073.
- Прокси не сохраняются в сцену и не попадают в билд; после перезагрузки скриптов они удаляются, а виды остаются.
