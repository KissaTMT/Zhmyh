# ArtDetails

Детали (глаза, рот, брови и т.п.) для арт-мешей **ArtMesh**. Деталь это обычный GameObject с простым мешем,
привязанный к месту на поверхности ArtMesh. У детали есть виды (как у ArtMesh), но вид хранит **только Transform**
(position, rotation, scale). Виды интерполируются по направлению камеры. Шейдер с маской не даёт детали выйти за границы
меша, на котором она стоит, даже когда меш деформируется.

- Система работает **поверх ArtMesh** и только читает его публичный API. Файлы ArtMesh не изменялись.
- **Рантайм и редактор разделены** (две сборки). В рантайме нет ни одной функции редактора.
- Вся работа в редакторе идёт через окно **Tools → ArtDetails → Editor**. В редакторе нет MonoBehaviour.

---

## Требования

- Установлен ArtMesh (сборка `ArtMesh.Runtime`). ArtDetails ссылается только на неё.
- Unity 2020.2 или новее. Шейдер `ArtDetails/MaskedUnlit` на CG с `#pragma target 3.5`, Built-in
  (в URP/HDRP проверь на своём проекте).
- Меш ArtMesh должен быть **читаемым** (`Read/Write`): привязка и маска считают позиции его вершин на CPU.
  Меш, запечённый ArtMesh Editor, читаем по умолчанию.

## Установка

Скопируй папку `ArtDetails` в `Assets/` рядом с `ArtMesh`.

| Сборка | Папка | Содержит |
|---|---|---|
| `ArtDetails.Runtime` | `Runtime/` | компонент, данные, смешивание поз, силуэт, шейдер |
| `ArtDetails.Editor` (только Editor) | `Editor/` | окно, вкладки, привязка, редактирование видов |

Пространства имён: `ArtDetails` и `ArtDetails.Editor`.

---

## Быстрый старт

1. Выбери объект с `ArtMeshRenderer` и нажми **GameObject → ArtDetails → Art Detail (Quad)**. Создастся `Art Detail`
   (дочерний объект цели) с квадом `Visual` и материалом `Assets/ArtDetails/ArtDetailDefault.mat` на шейдере
   `ArtDetails/MaskedUnlit`. Откроется окно ArtDetails Editor.
2. Вкладка **Setup**: «Создать ArtDetailAsset…» (в нём сразу есть вид Base).
3. Поставь деталь на нужное место меша (в Scene View) и нажми **«Привязать к позиции детали»**. Красная сфера в
   Scene View это точка привязки.
4. Вкладка **Views**: включи предпросмотр направления (или поворачивай камеру), нажми **«+ Вид из текущего»** и двигай
   деталь инструментами Unity (W/E/R). Изменения пишутся в вид сразу. Повтори для остальных ракурсов.
5. «Стоп» завершает редактирование вида.

## Как это устроено

**Привязка.** Точка привязки это треугольник меша ArtMesh и барицентрические координаты. Каждый кадр она считается
по итоговым (деформированным) позициям вершин этого треугольника, поэтому деталь едет вместе с деформацией:
сеткой, правками вершин, scale и offset видов ArtMesh. Позиция в базовой форме тоже хранится, так что после
перепекания меша деталь можно **перепривязать**.

**Вид детали (`ArtDetailView`).** Направление (yaw 0…360, pitch −90…90, как у видов ArtMesh) и Transform:

| Поле | Смысл |
|---|---|
| `position` | относительно точки привязки, в осях ArtMesh-детали (Z = глубина, +Z к «перед» детали) |
| `euler` | поворот в градусах |
| `scale` | масштаб |

**Смешивание.** Вес вида = 1 / (угол до направления камеры)^`weightPower` (как у ArtMesh). Позиция и масштаб
смешиваются линейно, поворот как взвешенное среднее кватернионов с выравниванием знака (проверено: среднее 350° и 10°
даёт 0°). Направление берётся у цели: `ArtMeshRenderer.Yaw/Pitch`.

**Итоговый Transform** (локальный, в осях ArtMesh-детали): `localPosition = точка привязки + position`,
`localRotation = rotation`, `localScale = scale`.

**Контракт.** Деталь должна быть **прямым дочерним объектом** GameObject с `ArtMeshRenderer`. Тогда её локальный
Transform совпадает с осями ArtMesh. Если это не так, окно предложит «Сделать дочерним к цели».

**Порядок работы.** Компонент `ArtDetail` выполняется после `ArtMeshRenderer` (`DefaultExecutionOrder(50)`), поэтому
читает уже посчитанное состояние цели.

## Маска силуэта

Деталь не рисуется за границами меша-цели. Механика:

1. Каждый кадр из итоговых позиций вершин **внешнего кольца** цели строится многоугольник силуэта в осях ArtMesh-детали
   (до 128 точек; по числу лучей меша).
2. Многоугольник и матрица «мир → оси детали» уходят в материалы детали через `MaterialPropertyBlock`.
3. Фрагментный шейдер переводит мировую позицию в оси цели, проверяет попадание в многоугольник (чётно-нечётное правило)
   и отбрасывает фрагменты снаружи. `Mask → Inset` отодвигает границу внутрь.

Плюсы: не нужны stencil и перерисовка меша цели, работает с любым порядком отрисовки и не зависит от шейдера ArtMesh.
Ограничения: маска проверяет только XY в осях цели (глубина игнорируется); цель должна быть радиальным мешем ArtMesh;
стоимость растёт с числом точек (цикл по рёбрам на фрагмент), для небольших деталей это дёшево, для детали на пол-экрана
стоит ужать число лучей. Силуэт на кадр кэшируется, несколько деталей на одной цели считают его один раз.

Маска работает с материалами на шейдере `ArtDetails/MaskedUnlit` (цвет `_Color`, необязательная текстура `_MainTex`
и отсечение по альфе `_Cutoff`). Для деталей из нескольких мешей (белок, зрачок, блик) задай им этот шейдер.

## Окно ArtDetails Editor

Открывается через **Tools → ArtDetails → Editor** или кнопкой в инспекторе `ArtDetail`. Следует за выбором; кнопка **Lock**
фиксирует цель.

### Вкладка Setup
- Цель (`ArtMeshRenderer`) и ассет видов. Проверки подсказывают, чего не хватает (нет привязки, неверная иерархия,
  меш нечитаем, привязка устарела, у рендерера не тот шейдер).
- **Привязка:** «Привязать к позиции детали», «Перепривязать (после Bake)», «Сбросить».
- **Маска:** включение и отступ.

### Вкладка Views
- Предпросмотр направления без камеры (yaw, pitch).
- Список видов: имя, направление, position, euler, scale и кнопки «Редактировать», «Взять направление»,
  «Записать трансформ», «Сброс», «X».
- «+ Base» (нулевая поза на yaw 0), «+ Вид из текущего» (текущая поза в текущем направлении).

**Редактирование вида.** На время сессии цель показывает направление вида (источник вида ArtMesh подменяется через его
публичный слой `ViewSource`), деталь перестаёт управляться компонентом и её можно двигать любыми инструментами Unity.
Каждый кадр Transform детали записывается в вид (абсолютная синхронизация, Undo/Redo работают).

Не используй одновременно с окном ArtMesh Editor на одной цели: оба подменяют `ViewSource`.

## Использование в рантайме

Компонент `ArtDetail` работает сам. Полезное API:

```csharp
var detail = GetComponent<ArtDetails.ArtDetail>();
detail.Asset = myAsset;
detail.Mask.enabled = true;
detail.Mask.inset = 0.01f;
detail.Driving = false;          // не писать Transform (двигает аниматор, скрипт)
```

### Источники позы (отдельный слой)

Откуда деталь берёт позу, определяет `IArtDetailPoseSource`:

| Источник | Поведение |
|---|---|
| `DirectionPoseSource` (по умолчанию) | по направлению цели, виды смешиваются |
| `FixedPoseSource(view)` / `FixedPoseSource(pose)` | одна поза без смешивания |

```csharp
detail.PoseSource = new ArtDetails.FixedPoseSource(viewAsset.views[0]);   // тест: одна поза
detail.PoseSource = null;                                                  // вернуть по направлению
```

Свой источник это реализация интерфейса. `ApplyPose(pose)` и `ReadPose()` позволяют записать и прочитать позу
относительно точки привязки.

## Данные

- `ArtDetailAsset` (ScriptableObject): список видов и `weightPower`. Данных редактора нет.
- Привязка и настройки маски хранятся в компоненте `ArtDetail` (они относятся к конкретному объекту на сцене).
  Один ассет видов можно использовать на нескольких деталях и персонажах: позиции заданы относительно точки привязки.

### Runtime (`ArtDetails`)

| Класс | Ответственность |
|---|---|
| `ArtDetailAsset`, `ArtDetailView`, `ArtDetailBinding`, `ArtDetailMaskSettings`, `ArtDetailPose` | данные |
| `ArtDetailPoseBlender` | смешивание видов в позу |
| `IArtDetailPoseSource`, `DirectionPoseSource`, `FixedPoseSource` | откуда берётся поза |
| `ArtDetailAnchorResolver` | точка привязки на деформированной поверхности |
| `SilhouetteCalculator`, `SilhouetteCache` | силуэт цели (многоугольник), кэш на кадр |
| `ArtDetailMaskBinder` | передача маски в материалы |
| `ArtDetail` | тонкий компонент (ленивая инициализация, `EnsureInitialized`) |
| `ArtDetailMasked.shader` | отрисовка с маской |

### Editor (`ArtDetails.Editor`)

| Группа | Классы |
|---|---|
| Привязка | `TriangleLocator`, `DetailBinder` |
| Виды и проверки | `DetailViewOperations`, `DetailValidator`, `DetailObjectCreator` |
| Сессия | `DetailEditSession` |
| Сцена | `DetailGizmos` |
| Окно | `ArtDetailEditorWindow` (хост), `ArtDetailEditorContext` (состояние), `DetailSetupTab`, `DetailViewsTab`, `ArtDetailInspector` |

## Ограничения и частые проблемы

- **Деталь «не привязана».** Привяжи на вкладке Setup. Без привязки компонент не пишет Transform (деталь остаётся где стоит).
- **Привязка устарела.** После перепекания меша (Bake) нажми «Перепривязать».
- **Деталь не обрезается.** Проверь шейдер материала (`ArtDetails/MaskedUnlit`), включена ли маска, радиальный ли меш цели.
- **Деталь прыгает или стоит не там.** Проверь, что она прямой дочерний объект цели.
- **Привязка и маска не работают в билде.** Меш цели должен быть читаемым (`Read/Write`).
- **Поворот привязки не наследуется.** Точка привязки задаёт только позицию; поворот и масштаб детали задаются видами.
  Если деталь должна поворачиваться вместе с деформацией, это делается через виды.
- Поворот смешивается как усреднение кватернионов: для очень далёких поз (больше ~120°) промежуточные значения
  приблизительные, добавь промежуточный вид.
